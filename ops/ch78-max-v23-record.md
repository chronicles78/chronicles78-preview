# Сверка установленного Хранителя: 27.10.2026

## Результат

Репозиторий восстановлен до фактически установленного worker v23. Все 12 файлов worker и все 6 файлов webhook v9 точно совпадают с полученными серверными исходниками. Собственные файлы miniapp v8 также совпадают.

Общий `ch78-max-assistant/handler.mjs` в репозитории соответствует встроенному помощнику worker v23. Работающая miniapp v8 ещё содержит более раннюю встроенную копию этого общего модуля; отдельная assistant v6 тоже не обновлялась. Поэтому совпадение всех сервисов с одной ревизией общего модуля не заявляется. Следующий выпуск miniapp/assistant требует собственной проверки. Подробная сверка — `ch78-max-v23-source-state.json`.

Новых развёртываний и изменений действующей базы в рамках этой сверки не было. Рабочий режим реакций — `draft`, лимит миниприложения — 5. Автоматические самостоятельные публикации не включались.

## Восстановленные миграции

Из сохранённой истории действующей базы дословно восстановлены четыре отсутствовавших файла:

- `20261026165900_ch78_max_main_chat.sql` — переключение активного архива с сохранением тестовых записей;
- `20261026172038_ch78_max_month_retrieval.sql` — поиск по месяцу публикации;
- `20261026181050_ch78_max_author_context.sql` — идентичность автора, его последние записи и явные связи ответов;
- `20261027173833_ch78_max_reaction_reply_context_v2.sql` — проверенные сведения об адресате ответа.

Эти изменения уже применены на сервере. При восстановлении истории их нельзя повторно применять к действующей базе как новые миграции. У части ранних миграций в репозитории и сервере различаются исторические метки времени. Сначала нужна отдельная сверка/согласование истории, прежде чем использовать автоматический `db push` против действующего проекта. Данные архива не копировались в репозиторий.

Операционные SQL-скрипты теперь относятся к основному чату. Отчёт о расходе использует активный архив из конфигурации. Команды generate/send из `ch78-max-refresh-dispatch.sql` точно сверены с действующим планировщиком. Скрипты не запускались и флаги не переключались.

## Поведение и проверки

В исходниках сохранены решения reply/clarify/defer/silence, скрытый кандидат defer, ранние бесплатные решения о невмешательстве, историческая дата, запрет будущих источников и передача автора/адресата. Исправлены ограничения Unicode для текстов с эмодзи. Поиск продолжения у автора оставляет конкретное действие отдельным запросом и не угадывает личность при неоднозначности.

Проверки на Node.js 24:

- **128** проверок HTTP-обработчиков и их взаимодействий;
- **104** проверки PostgreSQL/PGlite, включая новую схему основного архива и полный порядок 15 структурных миграций MAX;
- **9** проверок локального клиента Python;
- Deno 2.5.4: успешная проверка четырёх точек входа;
- синтаксис `keeper/app.mjs` и `git diff --check`.

Восстановление структуры архива проверено отдельно от расширений hosted cron/net. Работа планировщика проверяется собственными SQL-тестами с заглушками внешних эффектов. Полное восстановление всего сайта, резервной копии данных и облачной инфраструктуры этими тестами не заявляется.

Проверены неоднозначное имя, выбор по полной идентичности, хронология последних восьми записей, границы дат Samara, отсутствие межчатового смешения, права служебных RPC, скрытый черновик defer и отсутствие будущих свидетельств. В GitHub используются только вымышленные примеры.

Рабочий процесс проверок теперь автоматически включает новые `ch78-max-*.test.mjs`, а не только прежний фиксированный список.

## Смысловая приёмка

Автоматические проверки не заменяют оценку ответов настоящей модели. Закрытая серия должна отдельно оценивать полноту, подтверждение источниками, правильное понимание автора и уместность интонации. При неоднозначном имени ожидается уточнение до обращения к модели. Готовить эталоны следует по частному архиву, не публикуя тексты переписки в GitHub.

На момент этой сверки дневной бюджет миниприложения исчерпан. Новые платные пробы не выполнялись; лимит и записи квоты не менялись.

Ветка основана на `feat/ch78-max-003-jobs` (7019c71) и предназначена для отдельной проверки поверх существующей цепочки MAX. Слияние и публикация сайта в этот этап не входят.
