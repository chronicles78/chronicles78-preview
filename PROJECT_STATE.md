## 1. Что это за проект

**«Хроники-78»** — интерактивный закрытый архив выпускников школы №78 Куйбышева, выпуск 1983 года.

Идея проекта: не сухая база данных, а **книга + живой архив**.

Девиз:

> **Книга, которую можно читать. Память, по которой можно ходить.**

Основные разделы:

- Главная
- Чат
- Люди
- Истории
- Фото
- Город и время
- Открытые вопросы
- Профиль

Редакционный принцип: разные воспоминания могут не совпадать; версии участников не сводятся насильно к одной «официальной истине». Собственные и архивные фото могут подтверждать факт, внешние изображения используются только как атмосфера.

## 6. Авторизация и персональные данные

### Вход

Основной сценарий — **passwordless e-mail / Magic Link**.

Для существующего пользователя:

1. ввести e-mail;
2. получить одноразовую ссылку;
3. открыть письмо;
4. войти без пароля.

Старый парольный вход оставлен как резервный.

### Первый вход

Новый пользователь указывает:

- имя;
- e-mail;
- согласие на обработку персональных данных и использование изображения внутри закрытого архива.

Отдельного ручного одобрения администратора для обычного первого входа не требуется, если профиль создан корректно и согласие принято.

### Согласие

Текущая версия:

`2026-09-30-v3`

Охватывает:

- ФИО / имя;
- e-mail;
- сведения профиля;
- изображение человека на архивных и загруженных фото;
- сообщения;
- воспоминания;
- комментарии и материалы пользователя.

Согласие относится к **закрытому архиву**. Оно не является автоматическим разрешением на открытую публикацию в интернете, социальных сетях или рекламе.

Состояние согласия хранится в `user_consents`.

В профиле предусмотрены запросы:

- отзыв согласия;
- ограничение использования фотографии;
- исправление данных;
- удаление данных;
- иные вопросы приватности.

## 7. Фотоархив

### Три рабочих слоя

1. `archive-originals` — оригиналы.
2. `archive-pending` — облегчённые превью заявок до модерации.
3. `archive-media` — рабочие изображения, которые показывает сайт.

`chat-media` используется для вложений чата.

Все четыре bucket private.

### Лимиты

- `archive-originals` — до **25 МБ** на файл.
- `archive-media` — до **10 МБ**.
- `archive-pending` — до **10 МБ**.

### Автоматическая обработка

При загрузке архивной фотографии:

- оригинал сохраняется отдельно;
- рабочая версия уменьшается до **не более 1920 px по длинной стороне**;
- основной целевой формат — WebP;
- metadata оригинала и рабочей версии сохраняются отдельно;
- для тяжёлых файлов имеется browser fallback.

### Пользовательская очередь

Обычный участник может предложить фотографию.

Она проходит:

`original -> pending preview -> editor review -> archive-media`

Редактор может принять или отклонить фото.

Участник видит статус своей заявки.

## 12. Важные исправления, которые нельзя случайно откатить

### Коллективные фотографии

Исправлена ошибка, при которой уведомление о человеке 10А могло открывать фотографию 10Б.

При переходе к человеку:

- сначала определяется его группа;
- затем переключается `peopleGroup`;
- затем загружается нужная коллективная фотография;
- только после этого выбирается участник.

### Идентификация лиц

Существуют проверки:

- suggestion должен соответствовать реальной паре photo/person;
- подтверждение не должно молча перезаписывать уже подтверждённое другое имя;
- конкурирующие pending suggestions отклоняются после принятия одной версии;
- редактор видит crop лица при проверке предложения;
- «Не установлено» не должно превращаться в подтверждённое имя.

### Фото

Не возвращать прямую загрузку тяжёлых оригиналов в `archive-media`.

Рабочая страница должна использовать только оптимизированные версии и lazy loading.

## 64. Техническая модерация: устранены race condition навигации и телеметрии — 2026-10-02

### 64.1. Межраздельная навигация
- Проведён статический регрессионный аудит цепочек `Главная / Люди / Истории / Фото / Город / Вопросы / Уведомления`.

- На быстром desktop такой переход часто успевал отработать; на iPhone/Safari, при медленной сети, BFCache/background-resume и большом количестве signed URL целевой объект мог открываться до готовности данных.

  - прямые переходы из Главной, Людей, Фото, Города, Вопросов, поиска/тегов и Уведомлений теперь ждут целевой раздел и только затем открывают историю/фото/человека/этюд.
- В `openArchivePhoto()` и контекстной карточке фото добавлено точечное получение актуального signed URL непосредственно перед открытием. Это отделяет прямой переход к одной фотографии от фонового batch-prefetch всей галереи и одновременно обновляет протухший URL через общий cache.

### 64.2. Supabase / site-traffic
- Проверены логи Supabase за последние сутки.
- Из 92 ответов Edge Functions со статусом 422:
  - 84 относятся к историческому `drive-photo-import` deployment v7 — это уже закрытый инцидент старой ImageMagick/WASM-архитектуры; текущий importer v9 не является источником этих 84 ошибок;
