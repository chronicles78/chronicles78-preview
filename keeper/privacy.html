Для чего нужен читальный зал

Приложение проекта «Хроники‑78» помогает участникам нашей группы MAX находить сообщения и получать ответы по архиву. Сейчас для подключения подготовлен тестовый чат. Основную историю класса перенесём отдельно.

Проверка доступа

При открытии MAX передаёт подписанные данные запуска. Сервер проверяет подпись и срок действия, получает идентификатор пользователя и проверяет его текущее членство в группе через MAX. Имя или номер группы, введённые в запросе, не дают доступа к архиву.

Какие данные используются

Для работы нужны сообщения архива, имена авторов, даты публикации, ваш вопрос или поисковая фраза и идентификатор MAX. Служебный журнал хранит идентификатор запроса, пользователя, время, режим, состояние обработки и отпечаток запроса. Отпечаток — это не цифровой отпечаток устройства; он связывает номер запроса с его содержимым и защищает от повторного платного обращения.

Когда подключается OpenAI

При выборе «Спросить Хранителя» сервер передаёт вопрос и отобранные тексты сообщений с подписями источников в OpenAI API для подготовки ответа. Поиск может включать дополнительный запрос к модели для подбора ключевых слов. Данные обрабатываются внешним сервисом; его серверы могут находиться за пределами России. В запросах используется параметр store:false, который сам по себе не означает полного отсутствия технического хранения у провайдера.

Режим «Поиск по словам» выполняется на сервере проекта без обращения к OpenAI. Мини-приложение не передаёт в модель файлы вложений, фото и видео и не скачивает их автоматически.

Где хранятся данные

GitHub Pages размещает общедоступный интерфейс. Он не содержит сообщений закрытого архива. База архива, серверная обработка и временные результаты находятся в Supabase. MAX, GitHub, Supabase и OpenAI также обрабатывают технические сведения в рамках работы своих сервисов; эта страница не описывает их собственные журналы как журналы проекта.

Токены MAX, ключ базы и ключ OpenAI используются только сервером. Приложение не записывает архив, результаты и данные входа в локальное хранилище браузера. Ответы API выдаются с запретом кэширования. Это не исключает сохранения данных пользователем, например на скриншоте, или технической обработки клиентом MAX и поставщиками сервисов.

Сроки хранения

Архив сообщений сохраняется для работы проекта до решения об удалении материала или прекращения ведения архива. Временные результаты нужны, чтобы после обрыва связи можно было получить прежний ответ без повторного вызова ИИ. Записи этой служебной таблицы старше семи дней удаляются при следующем новом запросе к мини-приложению. Если запросов нет, очистка откладывается. Это правило не удаляет исходное сообщение из архива и не определяет сроки журналов поставщиков и резервных копий.

Кто видит результаты

Результат выдаётся тому пользователю, который создал запрос, после проверки членства в группе. Администратор проекта имеет технический доступ для обслуживания архива и рассмотрения обращений. Приложение само не публикует ответы в MAX и не делает архив общедоступным.
